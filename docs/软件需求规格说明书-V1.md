### 1.2 系统概述

观澜视频平台是一套面向内容观看者、平台用户与平台管理员的综合视频社区系统，目标是在 Web 端实现短视频、中视频、长视频与直播内容的一体化消费、创作、互动与治理闭环。系统以 B 站式社区主站为主体风格，首页入口借鉴抖音式推荐流，支持分区浏览、全局搜索、内容投稿、审核发布、弹幕评论、关注订阅、真实推流直播、录播回看、用户中心、审核后台与 Agent 审核辅助。

系统首版重点面向课程大作业交付，不追求商业平台级大规模分布式能力，但必须保证核心链路可运行、可展示、可测试、可文档化。

### 1.3 文档概述

本文档用于定义观澜视频平台首版的功能需求、非功能需求、接口需求、数据需求与约束条件，为后续概要设计、详细设计、接口开发、数据库设计、测试和验收提供基线。

本文档主要面向以下读者：

- 项目开发成员
- 项目文档编写成员
- 测试与部署成员
- 课程教师与助教

### 1.4 基线

本需求规格说明书基于以下已确认事实编写：

- 首版仅开发 Web 端
- 技术栈采用 Vue 3 + NestJS + MySQL + Redis + MinIO + SRS + FFmpeg
- 审核策略为先审后发
- 推荐采用规则版推荐
- 游客仅支持浏览与播放
- 视频弹幕与直播弹幕分开实现
- 支持录播回看
- 每日登录可领取礼物币，用于礼物兑换与发送
- 平台必须包含管理审核后台与 Agent 模块

## 3 需求

### 3.1 运行状态和模式

系统首版主要包含以下运行模式：

- 正常运行模式：面向游客、注册用户、用户和管理员提供服务
- 审核工作模式：管理员集中处理视频、评论、弹幕与举报审核
- 直播运行模式：用户开播、用户观看、聊天和发送直播弹幕
- 维护模式：仅运维或管理员可访问关键后台，普通用户暂不开放

### 3.2 需求概述

#### 3.2.1 业务目标

- 为普通用户提供统一的视频观看、直播观看、搜索、互动和订阅体验
- 为用户提供投稿、审核发布、直播开播、数据概览和违规提醒能力
- 为平台管理员提供审核、举报处理、用户处罚、运营查看和 Agent 审核辅助能力
- 通过规则推荐与内容分区设计，实现首版可解释的内容分发机制
- 通过先审后发策略和 Agent 辅助，实现基础社区治理能力

#### 3.2.2 运行环境

- 客户端：Chrome、Edge、Firefox 等现代浏览器
- 前端：Vue 3 + TypeScript + Vite
- 后端：NestJS + TypeScript
- 数据库：MySQL 8
- 缓存：Redis
- 对象存储：MinIO
- 媒体处理：FFmpeg
- 流媒体服务：SRS
- 部署方式：Docker Compose + Nginx

#### 3.2.3 用户特征

- 游客：无需注册即可浏览和播放，对页面访问速度和内容发现效率敏感
- 用户：以观看、互动、关注和送礼为主，期望评论、弹幕和通知反馈及时
- 用户：关注投稿效率、审核结果、作品数据、直播管理与违规提醒
- 管理员：关注审核效率、风险定位、处理闭环与平台治理可视化

#### 3.2.4 关键点

- 真实推流直播必须可演示，且直播后支持录播回看
- 审核策略为先审后发，未审核通过内容不得公开
- 首页分发采用规则版推荐，要求逻辑可说明、行为可追踪
- 视频弹幕和直播弹幕是两套不同交互机制
- Agent 模块只做审核辅助，不自动执行封禁或删除动作

#### 3.2.5 约束条件

- 开发周期必须与课程周次节点对齐
- 首版仅保证小并发稳定，不承诺大规模线上商用能力
- 不接入真实支付系统，礼物币仅做平台内模拟资产
- 不开发原生移动端 App
- 不允许直接照搬往届项目或成熟开源视频平台代码与文档

### 3.3 系统总体功能结构

#### 3.3.1 功能总览

系统功能划分为 8 个一级模块：

1. 用户与权限模块
2. 视频内容模块
3. 推荐与搜索模块
4. 互动模块
5. 直播模块
6. 用户中心模块
7. 审核与运营模块
8. 礼物币与 Agent 模块

#### 3.3.2 角色-功能映射

| 功能域 | 游客 | 用户 | 管理员 |
| --- | --- | --- | --- |
| 浏览首页/分区/搜索 | 是 | 是 | 是 |
| 播放公开视频/直播 | 是 | 是 | 是 |
| 点赞/收藏/评论/视频弹幕 | 否 | 是 | 是 |
| 关注用户 | 否 | 是 | 是 |
| 投稿与提交审核 | 否 | 是 | 是 |
| 开播与直播管理 | 否 | 是 | 是 |
| 用户中心数据看板 | 否 | 是 | 是 |
| 审核与举报处理 | 否 | 否 | 是 |
| 查看 Agent 审核建议 | 否 | 否 | 是 |

#### 3.3.3 业务主流程

- 视频投稿主流程：上传视频 -> 媒体处理 -> 提交审核 -> Agent 预审 -> 管理员审核 -> 发布上线
- 视频消费主流程：首页/分区/搜索 -> 视频详情 -> 点赞收藏评论弹幕 -> 关注/相关推荐
- 直播主流程：创建直播间 -> 开播推流 -> 直播观看 -> 聊天/直播弹幕/送礼 -> 结束直播 -> 录播回看
- 治理主流程：内容进入审核队列 -> Agent 给出风险建议 -> 管理员处理 -> 记录审计日志

### 3.4 核心需求定义

#### 3.4.1 CR-01 内容消费与分发

系统应提供首页推荐、频道分区、热门榜单、全局搜索、搜索结果 Tab、视频详情播放与相关推荐能力。公开视频在审核通过后方可出现在公开分发场景中。首页推荐应支持按规则排序，搜索应支持视频、直播、用户三类结果。

#### 3.4.2 CR-02 内容发布与审核

用户应能够上传视频、维护标题简介封面分区标签、提交审核、查看审核状态和驳回原因。视频需经历媒体处理和审核流程后方可发布。管理员应能够审核视频并执行通过、驳回、下架等处理。

#### 3.4.3 CR-03 社区互动

用户应能对视频进行点赞、收藏、评论、二级回复和发送视频弹幕。系统应提供消息通知，通知点赞、评论、回复、审核结果等事件。

#### 3.4.4 CR-04 关注订阅

用户应能关注或取关其他用户，查看用户主页、关注列表、粉丝关系和订阅流。用户主页应展示基础信息、作品列表和粉丝相关统计。

#### 3.4.5 CR-05 直播互动

用户应能创建直播间、进行真实推流开播、结束直播和查看录播。用户应能进入直播间观看直播、发送聊天消息、发送直播弹幕、使用礼物币发送礼物。直播结束后，系统应支持录播回看。

#### 3.4.6 CR-06 用户中心

用户应拥有独立的用户中心，包括数据概览、作品管理、直播管理、粉丝趋势、违规提醒和投稿入口。

#### 3.4.7 CR-07 平台治理与 Agent

系统应具备视频审核、评论审核、弹幕审核、举报处理、用户处罚、运营概览等能力。Agent 模块应为管理员提供风险等级、命中原因、建议动作和审核理由摘要等辅助信息。

### 3.5 功能需求规格

#### 3.5.1 用户与权限模块需求

##### FR-AUTH-01 注册

系统应支持用户名或邮箱注册，并设置密码。用户名和邮箱必须唯一。

##### FR-AUTH-02 登录

系统应支持用户名/邮箱 + 密码登录，并为登录用户签发访问令牌。

##### FR-AUTH-03 角色识别

系统应区分游客、用户、管理员三类角色，并基于角色限制接口和页面访问。

##### FR-AUTH-04 游客访问限制

游客可浏览首页、分区、搜索、视频详情和直播间，但不得进行点赞、收藏、评论、弹幕、关注、送礼、投稿、开播等操作。

##### FR-AUTH-05 用户资料管理

注册用户应能查看和编辑个人基础资料，包括昵称、头像、简介等。

##### FR-AUTH-06 安全控制

系统应支持退出登录、密码修改和基础异常登录校验。

#### 3.5.2 视频内容模块需求

##### FR-VIDEO-01 投稿上传

用户应能上传视频文件和封面，并填写标题、简介、分区、标签等元数据。

##### FR-VIDEO-02 草稿保存

用户在完成正式提交前，应能将投稿保存为草稿。

##### FR-VIDEO-03 媒体处理

视频上传后系统应触发媒体处理，包括时长提取、封面抽帧、基础转码等。

##### FR-VIDEO-04 审核提交

用户应能将可用草稿提交到审核队列，状态变更为待审核。

##### FR-VIDEO-05 审核结果反馈

用户应能查看视频的审核状态，包括待审核、已驳回、已发布、已下架等状态及处理原因。

##### FR-VIDEO-06 视频详情

公开视频应提供播放器、标题、简介、标签、发布者信息、评论区、相关推荐、视频弹幕等展示内容。

##### FR-VIDEO-07 视频分类

每个视频应至少归属一个业务分区，支持短/中/长视频统一内容模型。

#### 3.5.3 推荐与搜索模块需求

##### FR-DIST-01 首页推荐

系统应为用户提供首页推荐流，至少综合发布时间、播放量、点赞量、评论量、收藏量、分区偏好和关注关系等因素进行排序。

##### FR-DIST-02 分区浏览

系统应支持推荐、娱乐、学习、游戏、科技、直播六个一级分区的内容浏览。

##### FR-DIST-03 热门榜单

系统应支持输出热门视频或热门直播榜单，用于首页或频道页展示。

##### FR-DIST-04 全局搜索

系统应支持统一搜索入口，结果页按视频、直播、用户分 Tab 展示。

##### FR-DIST-05 搜索过滤

系统应支持基础排序或过滤能力，如按热度、时间等维度排序。

##### FR-DIST-06 相关推荐

视频详情页应支持相关推荐列表。

#### 3.5.4 互动模块需求

##### FR-INT-01 点赞与取消点赞

登录用户应能对公开视频进行点赞和取消点赞。

##### FR-INT-02 收藏与取消收藏

登录用户应能收藏视频并在个人中心查看收藏记录。

##### FR-INT-03 评论

登录用户应能在视频下发表评论。

##### FR-INT-04 二级回复

系统应支持对一级评论进行二级回复。

##### FR-INT-05 视频弹幕

登录用户应能在视频播放时间轴上发送普通滚动弹幕。

##### FR-INT-06 通知

系统应在收到点赞、评论、回复、关注、审核结果等事件时生成通知。

##### FR-INT-07 举报

登录用户应能对视频、评论或弹幕发起举报。

#### 3.5.5 关注订阅模块需求

##### FR-FOLLOW-01 关注与取关

登录用户应能关注或取消关注用户。

##### FR-FOLLOW-02 订阅流

系统应提供订阅内容流，用于展示已关注用户发布的内容。

##### FR-FOLLOW-03 用户主页

用户主页应展示头像、昵称、简介、粉丝数、关注数、作品列表和直播相关入口。

##### FR-FOLLOW-04 粉丝关系统计

用户中心应展示基础粉丝增长趋势和数量统计。

#### 3.5.6 直播模块需求

##### FR-LIVE-01 创建直播间

用户应能创建直播间，并配置标题、封面、分区等基础信息。

##### FR-LIVE-02 开播推流

用户应能获取推流地址与推流密钥，使用推流工具进行真实开播。

##### FR-LIVE-03 直播播放

用户应能进入直播间观看直播画面。

##### FR-LIVE-04 直播聊天

登录用户应能在直播间发送聊天消息。

##### FR-LIVE-05 直播弹幕

登录用户应能在直播间发送直播弹幕，直播弹幕与视频弹幕应在存储与分发上分离。

##### FR-LIVE-06 直播录播

直播结束后系统应生成基础录播资源，并提供录播回看入口。

##### FR-LIVE-07 直播状态管理

系统应支持直播间状态变化，包括创建、准备中、直播中、已结束、已封禁。

#### 3.5.7 用户中心模块需求

##### FR-CREATOR-01 数据概览

用户应能查看播放量、点赞量、评论量、粉丝变化等基础统计。

##### FR-CREATOR-02 作品管理

用户应能查看自己的投稿列表、审核状态、发布时间和作品详情入口。

##### FR-CREATOR-03 作品编辑

用户应能对草稿或被驳回作品进行重新编辑并再次提交审核。

##### FR-CREATOR-04 直播管理

用户应能查看直播间列表、历史直播、录播入口和开播状态。

##### FR-CREATOR-05 粉丝趋势

系统应提供时间维度的粉丝增长趋势展示。

##### FR-CREATOR-06 违规提醒

当作品或直播存在违规或驳回记录时，系统应在用户中心中提示。

#### 3.5.8 审核与运营模块需求

##### FR-REVIEW-01 视频审核

管理员应能查看待审核视频列表，并进行通过、驳回等操作。

##### FR-REVIEW-02 评论审核

管理员应能查看被举报评论或高风险评论，并执行删除、保留等处理。

##### FR-REVIEW-03 弹幕审核

管理员应能查看视频弹幕或直播弹幕中的高风险内容并处理。

##### FR-REVIEW-04 举报处理

管理员应能查看举报记录、举报原因、被举报对象及处理结果。

##### FR-REVIEW-05 用户处罚

管理员应能对违规用户执行禁言、封禁等基础处罚操作。

##### FR-REVIEW-06 运营概览

管理员应能查看基础运营统计，如视频总数、待审数、直播场次数、举报量等。

#### 3.5.9 礼物币与 Agent 模块需求

##### FR-GIFT-01 每日领取礼物币

登录用户应能每日首次登录领取一笔固定礼物币。

##### FR-GIFT-02 钱包记录

系统应记录礼物币余额和每日领取流水。

##### FR-GIFT-03 直播送礼

登录用户应能在直播间消耗礼物币发送礼物，系统应记录送礼对象、礼物类型和数量。

##### FR-AGENT-01 风险识别

Agent 应能对标题、简介、评论、弹幕等文本内容给出基础风险识别结果。

##### FR-AGENT-02 风险分级

Agent 输出应包含风险等级，如低风险、中风险、高风险。

##### FR-AGENT-03 审核建议

Agent 输出应包含建议动作与理由摘要，供管理员参考。

##### FR-AGENT-04 人工主导

系统不得在首版中依据 Agent 输出自动执行封禁、删除或驳回，最终处理动作由管理员确认。

### 3.6 外部接口需求

#### 3.6.1 用户接口

- 主站 Web 页面
- 用户中心 Web 页面
- 管理后台 Web 页面
- 直播推流工具（如 OBS）

#### 3.6.2 软件接口

- MySQL 数据库接口
- Redis 缓存接口
- MinIO 对象存储接口
- FFmpeg 命令行处理接口
- SRS 推流与播放接口
- 大模型或 Agent 推理接口

#### 3.6.3 通信接口

- HTTP/HTTPS RESTful API
- WebSocket 实时消息通道
- RTMP 推流协议
- HLS/HTTP-FLV 等直播播放协议

### 3.7 内部接口需求

- 前端与后端统一采用 JSON 返回格式 `{ code, message, data }`
- 后端模块之间通过服务层接口调用，不采用微服务远程调用
- 审核模块与 Agent 模块之间采用结构化输入输出对象
- 直播模块与通知模块之间通过事件或消息方式联动

### 3.8 内部数据需求

系统应至少维护以下核心数据对象：

- 用户数据
- 角色与权限数据
- 视频元数据与媒体资产数据
- 视频审核数据
- 评论与回复数据
- 视频弹幕数据
- 关注关系数据
- 直播间和直播场次数据
- 聊天消息与直播弹幕数据
- 录播数据
- 礼物币钱包与流水数据
- 举报记录与审计日志
- Agent 审核结果数据
- 通知数据

### 3.9 环境需求

- 开发环境支持 Node.js 20+
- 支持 MySQL、Redis、MinIO、SRS、FFmpeg 的本地或服务器部署
- 支持 Docker Compose 的统一演示部署

### 3.10 计算机资源需求

#### 3.10.1 硬件需求

- CPU：4 核及以上
- 内存：8GB 及以上
- 存储：预留足够视频素材、录播与数据库空间

#### 3.10.2 软件需求

- Node.js 20+
- Docker / Docker Compose
- MySQL 8
- Redis
- FFmpeg
- SRS
- Nginx

### 3.11 软件质量因素

#### 3.11.1 可用性

- 页面导航结构清晰
- 主流程交互可连续完成
- 用户和管理员入口明确分离

#### 3.11.2 性能

- 小并发下首页、视频详情、搜索结果等关键页面应稳定加载
- 普通交互接口在开发演示环境下应保持可接受响应时间

#### 3.11.3 安全性

- 密码必须加密存储
- 关键接口需做权限控制
- 上传内容需校验类型与大小
- 关键操作需记录审计日志

#### 3.11.4 可维护性

- 模块边界明确
- 接口命名统一
- 状态机设计清晰
- 文档与代码保持同步更新

#### 3.11.5 可扩展性

- 后续可扩展更复杂推荐算法
- 后续可扩展更多直播互动玩法
- 后续可扩展更丰富的 Agent 能力

### 3.12 设计和实现约束

- 首版后端采用单体模块化设计，不采用微服务拆分
- 首版推荐采用规则版而非学习型推荐
- 首版礼物币仅模拟平台内资产，不支持真实支付
- 首版录播仅支持基础回看，不支持二次编辑

### 3.13 数据输入输出需求

#### 3.13.1 输入数据

- 用户注册信息、登录凭证、资料修改信息
- 视频文件、封面文件、标题、简介、标签、分区
- 评论文本、回复文本、视频弹幕文本、直播聊天消息、直播弹幕文本
- 直播间配置、推流元数据
- 举报原因、审核结果、处罚动作

#### 3.13.2 输出数据

- 推荐流、搜索结果、视频详情、用户主页
- 审核状态、驳回原因、违规提醒
- 用户数据看板、粉丝趋势、直播记录
- 管理后台统计、审核队列、举报处理结果
- Agent 风险建议与理由摘要

### 3.14 操作需求

- 需要支持常规浏览、检索、观看、互动、投稿、直播、审核操作
- 需要支持系统初始化演示数据和测试账号
- 需要支持直播结束后的录播生成与访问

### 3.15 故障处理需求

- 视频媒体处理失败时应标识失败状态并允许重试
- 推流异常中断时应标记直播异常结束或切换为结束状态
- Agent 接口不可用时，管理员仍应可人工审核
- 对象存储或数据库异常时，应记录错误日志并返回标准错误信息

### 3.16 算法说明

- 推荐算法采用规则评分，综合发布时间、互动量、分区偏好、关注关系等因素
- Agent 风险识别采用外部模型结果，不在首版内自行训练模型
- 视频弹幕按时间轴存储和展示，直播弹幕按实时广播分发

### 3.17 需求优先级

| 优先级 | 范围 |
| --- | --- |
| P0 | 登录、首页推荐、视频播放、投稿审核、直播开播、审核后台 |
| P1 | 评论回复、视频弹幕、关注订阅、用户中心、录播回看 |
| P2 | 礼物币送礼、运营看板、Agent 风险提示优化 |

## 4 合格性规定

系统验收时至少满足以下条件：

- 七项核心需求均有实现与演示映射
- 游客、用户、管理员三类角色权限区分明确
- 视频投稿到发布链路可演示
- 直播开播到录播回看链路可演示
- 视频弹幕与直播弹幕均可演示
- 管理后台可处理视频审核与举报记录
- Agent 可输出风险等级和建议动作
