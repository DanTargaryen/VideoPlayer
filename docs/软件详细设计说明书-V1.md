## 1 引言

### 1.1 编写目的

本文档在《软件概要设计说明书 V1》的基础上，对观澜视频平台首版的关键模块进行进一步细化，明确模块编号、输入输出、处理逻辑、核心流程、异常处理、界面要点和安全性能考虑，为后续前后端编码、数据库建模、接口联调和测试用例设计提供直接依据。

### 1.2 项目背景

观澜视频平台是软件工程基础课程“在线视频与直播网站”方向的交付系统，首版采用 Web 端形态，支持视频消费、内容发布、规则推荐、社区互动、真实推流直播、录播回看、用户中心、管理审核后台和 Agent 审核辅助。详细设计阶段的目标不是重写需求，而是把需求和概要设计进一步落到模块级实现。

- RTMP：直播推流协议

## 2 系统结构设计及子系统划分

### 2.1 子系统划分概览

系统划分为以下八个子系统：

1. 用户与权限子系统
2. 视频内容子系统
3. 推荐与搜索子系统
4. 互动子系统
5. 直播子系统
6. 用户中心子系统
7. 审核与运营子系统
8. 礼物币与 Agent 子系统

各子系统均由前端页面层、接口层、服务层和数据访问层组成。首版后端采用 NestJS 单体模块化结构，模块之间通过服务调用协作，不做远程微服务拆分。

### 2.2 核心流程顺序说明

#### 2.2.1 视频投稿顺序

用户前端提交视频文件 -> 上传接口写入对象存储 -> 生成草稿记录 -> 媒体处理服务触发 FFmpeg -> 更新视频时长与封面 -> 用户提交审核 -> Agent 生成预审建议 -> 管理员审核 -> 视频发布

#### 2.2.2 视频消费顺序

用户打开首页 -> 推荐服务返回公开视频列表 -> 用户进入视频详情页 -> 加载视频信息、评论、弹幕、相关推荐 -> 用户执行互动操作 -> 系统更新统计字段并触发通知

#### 2.2.3 直播顺序

用户创建直播间 -> 获取推流信息 -> 推流工具发流到 SRS -> 系统标记场次开始 -> 用户进入直播间观看 -> WebSocket 广播聊天与直播弹幕 -> 主播结束直播 -> 录播生成 -> 用户查看录播

#### 2.2.4 审核顺序

内容进入审核队列 -> Agent 分析文本风险 -> 管理员查看审核工作台 -> 执行通过/驳回/删除/处罚 -> 写入审计日志 -> 通知相关用户

### 2.3 模块依赖关系

- 用户与权限子系统为所有需要登录的模块提供身份上下文
- 视频内容子系统依赖媒体处理和审核服务
- 推荐与搜索子系统依赖视频、直播和用户数据
- 互动子系统依赖用户身份、视频实体和通知服务
- 直播子系统依赖 SRS、礼物币和通知能力
- 用户中心子系统依赖视频、直播、粉丝和审核结果聚合能力
- 审核与运营子系统依赖 Agent、举报、视频、评论、弹幕和用户服务
- 礼物币与 Agent 子系统分别被直播和审核模块调用

## 3 功能模块详细设计

### 3.1 模块一：用户与权限子系统

#### 模块编号：UM-01

**模块名称**：用户注册与登录  
**对应需求**：FR-AUTH-01、FR-AUTH-02  
**输入**：`username`、`email`、`password`、`nickname` 或 `account`、`password`  
**处理**：

1. 注册时校验用户名和邮箱唯一性
2. 对密码做哈希加密后写入 `user`
3. 初始化 `user_profile` 与 `gift_coin_wallet`
4. 登录时通过用户名或邮箱查找用户
5. 校验密码并签发访问令牌
6. 更新最近登录时间

**输出**：用户基础信息、Token、角色信息  
**异常处理**：

- 用户名或邮箱重复返回参数冲突错误
- 密码错误返回认证失败
- 用户被封禁返回无权限错误

#### 模块编号：UM-02

**模块名称**：角色识别与权限控制  
**对应需求**：FR-AUTH-03、FR-AUTH-04  
**输入**：请求上下文、用户 Token、目标资源  
**处理**：

1. 解析 Token 获取用户身份
2. 判断当前请求是否允许游客访问
3. 对用户和管理员接口执行角色校验
4. 为下游服务注入当前用户上下文

**输出**：鉴权通过结果、当前用户上下文  
**异常处理**：

- Token 缺失或无效返回未登录错误
- 角色不符合要求返回无权限错误

#### 模块编号：UM-03

**模块名称**：用户资料维护  
**对应需求**：FR-AUTH-05、FR-AUTH-06  
**输入**：昵称、头像、简介、旧密码、新密码  
**处理**：

1. 更新 `user_profile` 中对应字段
2. 修改密码时校验旧密码
3. 敏感信息更新后记录审计信息

**输出**：更新后的用户资料  
**异常处理**：

- 资料字段格式错误返回参数错误
- 旧密码错误返回认证失败

### 3.2 模块二：视频内容子系统

#### 模块编号：VM-01

**模块名称**：视频文件上传  
**对应需求**：FR-VIDEO-01  
**输入**：视频文件、登录用户身份  
**处理**：

1. 校验文件格式和大小
2. 生成对象存储路径并上传至 MinIO
3. 返回上传令牌或资源 URL
4. 记录原始资源元数据

**输出**：上传结果、原始文件标识  
**异常处理**：

- 文件格式非法返回参数错误
- 上传失败返回服务错误

#### 模块编号：VM-02

**模块名称**：草稿创建与保存  
**对应需求**：FR-VIDEO-02  
**输入**：标题、简介、标签、分区、封面、上传令牌  
**处理**：

1. 创建或更新 `video`
2. 将状态设置为 `DRAFT` 或 `PROCESSING`
3. 保存视频标签关系
4. 关联原始视频资源和封面资源

**输出**：视频草稿对象  
**异常处理**：

- 关联资源不存在返回参数错误
- 非作者本人操作返回无权限错误

#### 模块编号：VM-03

**模块名称**：媒体处理任务  
**对应需求**：FR-VIDEO-03  
**输入**：视频 ID、原始视频 URL  
**处理**：

1. 调用 FFmpeg 解析时长、分辨率和关键帧
2. 生成截图或抽帧封面
3. 生成基础转码资源
4. 更新 `video_asset` 和 `video.duration_seconds`
5. 媒体处理完成后保持草稿可编辑状态

**输出**：处理状态、媒体资源列表  
**异常处理**：

- FFmpeg 处理失败将视频状态标记为 `DRAFT` 并记录失败原因
- 资源写入失败返回服务错误

#### 模块编号：VM-04

**模块名称**：视频审核提交流程  
**对应需求**：FR-VIDEO-04、FR-VIDEO-05  
**输入**：视频 ID、用户身份  
**处理**：

1. 检查视频是否存在且属于当前用户
2. 检查媒体处理是否完成
3. 切换状态为 `PENDING_REVIEW`
4. 创建 `video_review` 审核记录
5. 调用 Agent 预分析标题与简介文本

**输出**：待审核状态、审核记录 ID  
**异常处理**：

- 媒体处理未完成时拒绝提交
- 已发布视频不可重复提交

#### 模块编号：VM-05

**模块名称**：视频详情装配  
**对应需求**：FR-VIDEO-06、FR-VIDEO-07  
**输入**：视频 ID、当前用户身份  
**处理**：

1. 查询 `video` 和 `video_asset`
2. 组装发布者信息、标签、统计字段
3. 加载是否点赞、是否收藏、是否关注等用户态信息
4. 返回播放器信息和展示信息

**输出**：视频详情 DTO  
**异常处理**：

- 视频未发布且无权限查看时返回资源不可见错误
- 视频不存在返回 404

### 3.3 模块三：推荐与搜索子系统

#### 模块编号：RS-01

**模块名称**：首页推荐流  
**对应需求**：FR-DIST-01  
**输入**：分页参数、当前用户身份、可选分区  
**处理**：

1. 只筛选 `PUBLISHED + PUBLIC` 的视频
2. 根据发布时间、互动量、分区偏好、关注关系进行规则打分
3. 排序后返回分页列表

**输出**：推荐视频列表  
**算法说明**：

- `score = freshness_weight + interaction_weight + preference_weight + follow_weight`

**异常处理**：

- 用户未登录时退化为通用推荐

#### 模块编号：RS-02

**模块名称**：分区列表与热门榜单  
**对应需求**：FR-DIST-02、FR-DIST-03  
**输入**：分区编码、目标类型  
**处理**：

1. 查询分区下已发布内容
2. 根据热度字段排序
3. 输出频道列表或热门榜单

**输出**：分区列表、热榜数据  
**异常处理**：

- 分区不存在返回参数错误

#### 模块编号：RS-03

**模块名称**：全局搜索  
**对应需求**：FR-DIST-04、FR-DIST-05、FR-DIST-06  
**输入**：`keyword`、`tab`、`sortBy`、分页参数  
**处理**：

1. 对视频、直播、用户分别执行匹配
2. 根据 Tab 控制聚合或单类输出
3. 更新搜索热词计数
4. 视频详情页相关推荐可复用标签和分区相似度逻辑

**输出**：搜索结果页 DTO  
**异常处理**：

- 关键词为空返回参数错误

### 3.4 模块四：互动子系统

#### 模块编号：IM-01

**模块名称**：点赞与收藏  
**对应需求**：FR-INT-01、FR-INT-02  
**输入**：用户 ID、视频 ID、操作类型  
**处理**：

1. 校验用户已登录且视频可见
2. 写入或删除 `like_record`、`favorite`
3. 回写 `video.like_count` 或 `video.favorite_count`
4. 对点赞事件生成通知

**输出**：操作结果、最新计数  
**异常处理**：

- 重复点赞或重复收藏需幂等处理

#### 模块编号：IM-02

**模块名称**：评论与二级回复  
**对应需求**：FR-INT-03、FR-INT-04  
**输入**：视频 ID、评论内容、父评论 ID、根评论 ID  
**处理**：

1. 校验评论所属视频存在
2. 一级评论直接写入 `comment`
3. 二级回复写入 `parent_id` 和 `root_id`
4. 更新评论计数和回复计数
5. 触发评论通知

**输出**：评论对象  
**异常处理**：

- 父评论不存在返回参数错误
- 评论内容过长或命中敏感词返回校验失败

#### 模块编号：IM-03

**模块名称**：视频弹幕  
**对应需求**：FR-INT-05  
**输入**：视频 ID、内容、时间偏移、颜色  
**处理**：

1. 校验用户已登录
2. 校验时间偏移在视频时长范围内
3. 写入 `video_danmaku`
4. 播放时按时间窗口拉取弹幕列表

**输出**：弹幕发送结果、弹幕列表  
**异常处理**：

- 时间偏移超出范围返回参数错误
- 弹幕内容命中高风险规则时进入隐藏或待审状态

#### 模块编号：IM-04

**模块名称**：通知与举报  
**对应需求**：FR-INT-06、FR-INT-07  
**输入**：事件类型或举报对象类型、举报原因  
**处理**：

1. 点赞/评论/回复/关注/审核结果等事件写入 `notification`
2. 举报请求写入 `report_record`
3. 举报对象若为文本内容，可附带触发 Agent 风险分析

**输出**：通知结果、举报记录  
**异常处理**：

- 举报对象不存在返回参数错误
- 重复举报同一对象可做限流或合并处理

### 3.5 模块五：直播子系统

#### 模块编号：LM-01

**模块名称**：直播间创建与配置  
**对应需求**：FR-LIVE-01  
**输入**：标题、封面、分区、用户身份  
**处理**：

1. 创建 `live_room`
2. 生成 `stream_key`
3. 根据 SRS 配置生成 RTMP 地址和播放地址
4. 返回直播间配置数据

**输出**：直播间对象、推流信息  
**异常处理**：

- 非用户角色禁止创建直播间

#### 模块编号：LM-02

**模块名称**：开播与关播控制  
**对应需求**：FR-LIVE-02、FR-LIVE-07  
**输入**：直播间 ID、当前用户  
**处理**：

1. 开播时创建 `live_session`
2. 更新直播间状态为 `LIVING`
3. 结束直播时更新场次状态为 `ENDED`
4. 触发录播处理任务

**输出**：直播状态、场次对象  
**异常处理**：

- 已在直播中的房间不得重复开播
- 非房主操作返回无权限错误

#### 模块编号：LM-03

**模块名称**：直播间观看页  
**对应需求**：FR-LIVE-03  
**输入**：直播场次 ID 或直播间 ID  
**处理**：

1. 查询直播间、场次和播放地址
2. 返回主播信息、分区信息、在线状态
3. 装配聊天和送礼入口所需配置

**输出**：直播详情 DTO  
**异常处理**：

- 房间不存在或被封禁返回不可用错误

#### 模块编号：LM-04

**模块名称**：直播聊天与直播弹幕  
**对应需求**：FR-LIVE-04、FR-LIVE-05  
**输入**：场次 ID、用户 ID、消息内容  
**处理**：

1. 通过 WebSocket Gateway 接收消息
2. 对消息执行敏感词校验和频控
3. 写入 `live_chat_message` 或 `live_danmaku`
4. 广播给直播间在线用户

**输出**：发送确认、广播消息  
**异常处理**：

- 用户未登录禁止发送
- 直播不在 `LIVING` 状态时拒绝发送

#### 模块编号：LM-05

**模块名称**：录播生成与回看  
**对应需求**：FR-LIVE-06  
**输入**：直播场次 ID、SRS 录制产物  
**处理**：

1. 直播结束后创建 `live_recording`
2. 如有必要使用 FFmpeg 做格式处理
3. 将录播文件写入对象存储
4. 更新录播状态为 `READY`

**输出**：录播对象、回看地址  
**异常处理**：

- 录播处理失败时标记 `FAILED`
- 回看请求在录播未就绪时返回处理中状态

### 3.6 模块六：用户中心子系统

#### 模块编号：CM-01

**模块名称**：用户数据概览  
**对应需求**：FR-CREATOR-01  
**输入**：当前用户 ID、时间范围  
**处理**：

1. 聚合视频播放、点赞、评论和粉丝数据
2. 输出概览卡片数据和趋势数据

**输出**：Dashboard DTO  
**异常处理**：

- 非用户角色无权访问

#### 模块编号：CM-02

**模块名称**：作品管理  
**对应需求**：FR-CREATOR-02、FR-CREATOR-03  
**输入**：当前用户 ID、筛选条件  
**处理**：

1. 查询当前用户的视频列表
2. 按状态筛选草稿、待审、驳回、已发布作品
3. 返回编辑入口和审核状态信息

**输出**：作品管理列表  
**异常处理**：

- 非作者本人不可查看私有作品管理数据

#### 模块编号：CM-03

**模块名称**：直播管理与粉丝趋势  
**对应需求**：FR-CREATOR-04、FR-CREATOR-05、FR-CREATOR-06  
**输入**：当前用户 ID、时间范围  
**处理**：

1. 查询历史直播和录播记录
2. 统计粉丝增长趋势
3. 聚合违规提醒信息

**输出**：直播管理数据、粉丝趋势图数据、违规提醒列表  
**异常处理**：

- 数据为空时返回空列表，不视为错误

### 3.7 模块七：审核与运营子系统

#### 模块编号：AM-01

**模块名称**：视频审核工作台  
**对应需求**：FR-REVIEW-01  
**输入**：审核状态、分页参数、管理员身份  
**处理**：

1. 查询 `video_review` 待审记录
2. 关联视频信息和 Agent 风险结果
3. 管理员执行通过、驳回、下架动作
4. 更新 `video.status`
5. 写入 `audit_log` 和通知

**输出**：待审列表、审核处理结果  
**异常处理**：

- 非管理员访问返回无权限错误
- 状态冲突时拒绝重复审核

#### 模块编号：AM-02

**模块名称**：文本内容审核  
**对应需求**：FR-REVIEW-02、FR-REVIEW-03  
**输入**：文本对象类型、分页参数、风险等级过滤  
**处理**：

1. 聚合评论、视频弹幕、直播聊天、直播弹幕等对象
2. 关联举报信息和 Agent 风险结果
3. 管理员执行删除、保留、隐藏等动作
4. 记录审计日志

**输出**：文本审核列表、处理结果  
**异常处理**：

- 文本对象不存在时返回资源不存在

#### 模块编号：AM-03

**模块名称**：举报处理与用户处罚  
**对应需求**：FR-REVIEW-04、FR-REVIEW-05  
**输入**：举报记录 ID、处理动作、处罚原因  
**处理**：

1. 查询 `report_record`
2. 根据举报对象和历史行为决定处理动作
3. 更新举报状态
4. 如需处罚则更新用户状态或处罚记录
5. 写入审计日志

**输出**：举报处理结果、处罚结果  
**异常处理**：

- 已处理举报记录不可重复处理
- 非管理员角色无权处罚

#### 模块编号：AM-04

**模块名称**：运营概览  
**对应需求**：FR-REVIEW-06  
**输入**：时间范围  
**处理**：

1. 聚合视频数量、直播场次、待审数量、举报数量等指标
2. 输出仪表盘展示数据

**输出**：运营看板 DTO  
**异常处理**：

- 聚合失败返回服务错误

### 3.8 模块八：礼物币与 Agent 子系统

#### 模块编号：GM-01

**模块名称**：每日礼物币领取  
**对应需求**：FR-GIFT-01、FR-GIFT-02  
**输入**：当前用户 ID、当前日期  
**处理**：

1. 查询是否已领取当日礼物币
2. 未领取则写入 `gift_coin_daily_claim`
3. 增加 `gift_coin_wallet.balance`
4. 更新累计领取字段

**输出**：领取结果、钱包余额  
**异常处理**：

- 重复领取返回状态冲突

#### 模块编号：GM-02

**模块名称**：直播送礼  
**对应需求**：FR-GIFT-03  
**输入**：送礼人、主播、场次、礼物名称、单价、数量  
**处理**：

1. 校验直播处于 `LIVING`
2. 计算总消耗
3. 扣减钱包余额
4. 写入 `gift_order`
5. 通过 WebSocket 广播送礼事件

**输出**：送礼结果、最新余额  
**异常处理**：

- 余额不足返回业务错误
- 直播未开播时不允许送礼

#### 模块编号：GM-03

**模块名称**：Agent 风险分析  
**对应需求**：FR-AGENT-01、FR-AGENT-02、FR-AGENT-03、FR-AGENT-04  
**输入**：对象类型、文本内容、上下文元数据  
**处理**：

1. 组装提示词和分析上下文
2. 调用 Agent 服务接口
3. 解析返回的风险等级、命中规则和建议动作
4. 写入 `agent_review_result`
5. 将结果返回给审核模块

**输出**：风险结果 DTO  
**异常处理**：

- Agent 调用失败时记录错误并返回“人工审核优先”兜底结果
- 非法对象类型返回参数错误

- 侧边区域：相关推荐列表

### 4.3 用户界面设计原则

- 主站强调内容沉浸和快速消费

- 所有危险操作需二次确认

## 5 异常处理设计

### 5.1 错误分类

- 参数错误：输入缺失、格式错误、状态不合法
- 认证错误：未登录、Token 失效
- 权限错误：游客访问受限接口、用户访问管理员接口
- 业务错误：余额不足、重复领取、重复开播、重复审核
- 外部依赖错误：MinIO 不可用、FFmpeg 失败、SRS 不可用、Agent 超时

### 5.2 故障预防与补救

- 媒体处理失败可重试
- 录播生成失败保留失败状态并允许后台排查
- Agent 超时不阻断人工审核
- 直播异常中断时将场次状态标记为 `ABNORMAL`
- 所有关键异常写入日志和监控输出

### 5.3 系统维护设计

- 通过统一配置文件管理数据库、缓存、存储和直播服务地址
- 状态枚举和错误码集中维护
- 演示环境使用固定测试数据和脚本

## 6 性能与安全设计

### 6.1 性能优化设计

- 推荐流、分区流、搜索结果均采用分页
- 视频详情中统计字段采用冗余计数，避免高频聚合
- 热词和热点数据优先使用 Redis 辅助
- 视频弹幕按时间窗口查询，不一次性全量加载
- 直播聊天和直播弹幕通过 WebSocket 广播，避免轮询压力

### 6.2 安全设计

- 密码哈希存储
- 统一鉴权拦截
- 上传文件白名单校验
- 管理员操作写入审计日志
- 举报和处罚动作保留完整处理记录
- Agent 只提供建议，不自动执法
