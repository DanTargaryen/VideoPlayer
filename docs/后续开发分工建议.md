# 后续开发分工建议

## 1. 当前已完成情况

当前项目已经具备以下基础能力：

- 账号登录与角色区分（用户 / 管理员）
- 首页推荐流
- 搜索页基础版本
- 视频详情页
- 点赞、收藏、视频弹幕
- 评论、二级回复
- 用户主页、关注、关注流
- 通知中心
- 投稿、提交审核
- 管理员视频审核
- 评论/弹幕举报
- 文本审核与举报处理
- MySQL + Prisma 持久化

当前代码已经可以支持一轮中期演示，但离最终答辩还有若干需要补齐和打磨的部分。

## 2. 后续开发总目标

后续开发重点放在以下四个方向：

1. 直播侧能力补全
2. 主站体验细化与 UI 打磨
3. 后台治理与可观测性增强
4. 工程完善、测试、部署与答辩准备

## 3. 推荐的五人分工方案

### 成员 A：主站前端与 UI 负责人

负责范围：

- 首页视觉和卡片样式继续优化
- 搜索结果页完善（筛选、排序、空状态、结果提示）
- 用户主页和关注流样式优化
- 视频详情页相关推荐区和互动区样式优化
- 全站统一主题、间距、颜色、组件复用整理

交付物：

- 主站页面 UI 优化代码
- 可复用前端组件整理
- 用户手册中的用户端截图和说明

建议优先级：P1

### 成员 B：直播前端与互动展示负责人

负责范围：

- 直播间页面完善
- 直播聊天展示区
- 直播弹幕展示区
- 礼物交互展示优化
- 录播回看页完善
- 直播相关页面的 UI 风格统一

交付物：

- 直播页前端代码
- 录播页前端代码
- 直播演示脚本和截图素材

建议优先级：P0

### 成员 C：后端业务与数据负责人

负责范围：

- 搜索结果分页、排序、筛选参数增强
- 用户主页、关注流、推荐流的查询优化
- 点赞、收藏、评论、通知等接口细节完善
- 数据统计接口补全
- 统一异常处理、参数校验、DTO 清理

交付物：

- 业务接口完善
- 数据查询优化
- API 文档补充
- 数据库设计更新

建议优先级：P1

### 成员 D：直播后端与媒体处理负责人

负责范围：

- MinIO 真实上传接入
- 视频文件真实入库与 `video_asset` 方案补齐
- FFmpeg 转码、封面抽帧、时长提取
- SRS 直播推流链路打通
- 录播文件落盘与回看资源入库

交付物：

- 上传链路代码
- 媒体处理脚本或服务
- 直播推流/播放配置
- 部署文档中的媒体服务部分

建议优先级：P0

### 成员 E：后台治理、测试与文档负责人

负责范围：

- 管理后台继续完善（评论审核、弹幕审核、举报筛选、处理备注）
- Agent 提示结果展示优化
- 测试用例编写与执行
- 测试报告、部署文档、用户手册整合
- 答辩 PPT 和演示流程材料整理

交付物：

- 后台治理页代码
- 测试报告
- 部署文档
- 用户手册
- 答辩材料初稿

建议优先级：P0

## 4. 具体待完成任务清单

### 4.1 P0：必须继续完成

#### 任务 T1：真实视频上传到 MinIO

内容：

- 前端上传真实文件
- 后端接收文件并上传到 MinIO
- 返回文件 URL / object key
- 数据库记录资源元数据

完成标准：

- 用户可选择本地视频文件上传
- 上传后数据库可查到记录
- 页面可正常显示对应视频资源

责任建议：成员 D

#### 任务 T2：FFmpeg 媒体处理链路

内容：

- 视频时长解析
- 封面抽帧
- 基础转码
- 失败重试和状态更新

完成标准：

- 上传后的文件可自动生成封面
- 视频时长和播放资源可正确展示

责任建议：成员 D

#### 任务 T3：直播链路打通

内容：

- SRS 推流配置
- 开播状态切换
- 直播播放地址生成
- 录播文件生成与回看

完成标准：

- 能真实推流开播
- 前端直播间可播放
- 结束后能查看录播

责任建议：成员 B + 成员 D

#### 任务 T4：后台治理能力完善

内容：

- 举报筛选
- 评论/弹幕审核动作细化
- 后台处理备注展示
- 更清晰的治理看板

完成标准：

- 管理员能高效定位待处理内容
- 文本审核、举报处理、视频审核三区可流畅演示

责任建议：成员 E

#### 任务 T5：测试与部署闭环

内容：

- 补充功能测试用例
- 回归测试
- 部署脚本与操作说明
- 演示环境固化

完成标准：

- 新成员能按照文档独立跑起项目
- 答辩前有稳定演示环境

责任建议：成员 E + 成员 D

## 5. 建议的开发顺序

建议按以下顺序推进：

1. 真实上传到 MinIO
2. FFmpeg 媒体处理
3. 直播推流与录播打通
4. 后台治理继续完善
5. 搜索页和首页继续打磨
6. 测试、部署、答辩材料整理

## 6. 每位成员建议交付检查项

### 成员 A 检查项

- 首页、搜索页、详情页、用户主页是否统一风格
- 至少 4 个页面达到可答辩展示水平

### 成员 B 检查项

- 直播间、录播页、礼物区是否可演示
- 直播互动区域是否具备可见反馈

### 成员 C 检查项

- 搜索、推荐、详情、通知相关接口是否稳定
- API 文档和数据库设计是否同步更新

### 成员 D 检查项

- 上传、转码、推流、录播链路是否实际可跑
- 部署步骤是否可复现

### 成员 E 检查项

- 后台治理功能是否完整
- 测试报告和部署文档是否可以提交
- 答辩材料是否具备清晰演示路径

## 7. 答辩前必须确认的事项

- 所有演示账号是否可用
- MySQL、MinIO、SRS 是否能稳定启动
- 首页、详情、用户中心、后台、直播页是否均可打开
- 评论、弹幕、举报、审核链路是否能完整演示
- 所有过程文档是否与当前代码一致

## 8. 建议团队协作规则

- 每完成功能必须同步更新对应文档
- 每个成员提交前必须本地至少通过一次构建
- 影响数据库结构的改动必须先同步到团队
- 影响接口返回结构的改动必须同步前端负责人
