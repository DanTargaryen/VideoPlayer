# 候选业务场景（用例）范围

> 状态：`CONFIRMED`。组长于 2026-08-24 报告教师已确认 UC01-UC06；外部回复截图/链接待归档。
>
> 原则：业务场景是参与者为了一个明确目标，从触发到可验证结果的完整流程；页面、按钮、单个接口或单次数据库操作不单列为用例。

## 1. 范围规则

1. 候选范围先收敛为 6 个端到端业务场景。
2. 每个确认用例必须覆盖主成功流程、至少一个备选/异常流程和可验证结果。
3. AI 视频问答、全局助手、评论机器人、动态广场、私信、连续签到等功能优先作为现有用例中的备选能力，不默认扩大为独立用例。
4. 尚未稳定或只是设想的功能必须在 D1 向教师/助教说明并获得是否计入的确认。
5. 确认后的每个用例都使用同一编号贯穿需求、三层模型、代码、测试和报告。

## UC01 账户访问与资料维护

| 字段 | 内容 |
| --- | --- |
| 需求编号 | `REQ01` |
| 参与者 | 游客、普通用户、管理员 |
| 触发条件 | 游客希望注册/登录，或已登录用户希望查看和修改个人资料 |
| 前置条件 | 后端、数据库和验证码服务可用；测试账号/邮箱规则已准备 |
| 可验证结果 | 用户获得与角色一致的会话权限；资料修改持久化；未授权请求被拒绝 |
| 主要模块 | `auth`、`captcha`、`email`、`user`、前端登录/注册/用户主页 |
| 追溯编号 | `SYS-SEQ01`、`COMP-SEQ01`、`OBJ-SEQ01`、`UNIT-TC01`、`INT-TC01`、`E2E-TC01` |

主成功流程：

1. 游客进入注册或登录入口。
2. 系统验证验证码、账号信息和密码。
3. 系统创建或查找用户，签发身份凭据。
4. 前端进入与角色匹配的页面。
5. 用户修改昵称、头像或简介。
6. 刷新或重新登录后，修改结果仍然存在。

备选/异常流程：验证码错误；用户名/邮箱重复；密码错误；会话过期；普通用户尝试访问管理员接口；管理员入口密钥错误。

## UC02 视频发现、播放与观看记录

| 字段 | 内容 |
| --- | --- |
| 需求编号 | `REQ02` |
| 参与者 | 游客、普通用户 |
| 触发条件 | 用户希望通过推荐、分区或搜索找到并观看视频 |
| 前置条件 | 存在已发布视频和可访问媒体；推荐/搜索接口可用 |
| 可验证结果 | 只返回可公开内容；视频可播放；已登录用户形成可查询观看记录 |
| 主要模块 | `feed`、`search`、`video`、`media-proxy`、首页/分区/搜索/视频详情 |
| 追溯编号 | `SYS-SEQ02`、`COMP-SEQ02`、`OBJ-SEQ02`、`UNIT-TC02`、`INT-TC02`、`E2E-TC02` |

主成功流程：

1. 用户从首页、分区或搜索输入业务条件。
2. 系统返回符合发布状态和筛选条件的视频列表。
3. 用户进入视频详情并加载媒体、评论和相关推荐。
4. 用户开始播放并上报播放/进度。
5. 已登录用户在观看历史中看到本次记录。

## UC03 投稿、媒体处理、审核与发布

| 字段 | 内容 |
| --- | --- |
| 需求编号 | `REQ03` |
| 参与者 | 创作者、管理员、MinIO、FFmpeg |
| 触发条件 | 创作者希望上传作品并公开发布 |
| 前置条件 | 用户已登录；MinIO、数据库和媒体处理能力可用；管理员账号存在 |
| 可验证结果 | 原始文件和资产元数据可查；审核前不公开；通过后公开或驳回后展示原因 |
| 主要模块 | `video`、`storage`、`creator`、`admin`、`agent`、`ai`、投稿/创作者/管理后台 |
| 追溯编号 | `SYS-SEQ03`、`COMP-SEQ03`、`OBJ-SEQ03`、`UNIT-TC03`、`INT-TC03`、`E2E-TC03` |

主成功流程：

1. 创作者选择视频、封面和元数据。
2. 后端上传原始文件到 MinIO，并登记 `VideoAsset`。
3. FFmpeg 提取时长、抽帧或转码，系统更新媒体结果。
4. 创作者保存稿件并提交审核。
5. 管理员查看待审内容和辅助建议。
6. 管理员通过后，视频状态变为 `PUBLISHED` 并进入发现/播放范围。

备选/异常流程：上传超时；文件类型/大小不合法；MinIO 不可用；FFmpeg 失败；重复提交；审核服务不可用；管理员驳回并填写原因；创作者修改后重提。

## UC04 视频互动、关注与通知

| 字段 | 内容 |
| --- | --- |
| 需求编号 | `REQ04` |
| 参与者 | 普通用户、创作者 |
| 触发条件 | 用户希望对视频表达反馈、保存内容或持续关注创作者 |
| 前置条件 | 用户已登录；目标视频/用户存在且允许互动 |
| 可验证结果 | 点赞/收藏/评论/弹幕/关注状态持久化；计数一致；相关通知可查询 |
| 主要模块 | `comment`、`follow`、`notification`、`video`、`report`、视频详情/关注流/通知页 |
| 追溯编号 | `SYS-SEQ04`、`COMP-SEQ04`、`OBJ-SEQ04`、`UNIT-TC04`、`INT-TC04`、`E2E-TC04` |

主成功流程：

1. 登录用户进入已发布视频详情。
2. 用户执行点赞、收藏、评论/回复、弹幕或关注中的一项或多项。
3. 系统保存去重关系和内容，更新对应计数。
4. 被互动用户收到相关通知。
5. 用户从收藏夹、关注流或通知页验证结果。

备选/异常流程：游客操作；重复点赞/收藏/关注；目标不存在；违规文本；评论被删除；通知创建失败但主体操作已成功；取消操作。

## UC05 直播、互动、礼物与录播回看

| 字段 | 内容 |
| --- | --- |
| 需求编号 | `REQ05` |
| 参与者 | 主播、观众、SRS、MinIO |
| 触发条件 | 主播希望开播，观众希望观看和互动，结束后希望回看 |
| 前置条件 | 主播/观众账号存在；SRS、MinIO 和数据库可用；浏览器媒体权限允许 |
| 可验证结果 | 直播状态可恢复/查询；观众可观看并互动；结束后生成可登记和播放的录播 |
| 主要模块 | `live`、`gift`、`storage`、`video`、直播页/创作者中心 |
| 追溯编号 | `SYS-SEQ05`、`COMP-SEQ05`、`OBJ-SEQ05`、`UNIT-TC05`、`INT-TC05`、`E2E-TC05` |

主成功流程：

1. 主播创建直播间并选择摄像头/屏幕来源。
2. 系统生成推流/播放信息，主播开始直播。
3. 观众在直播广场进入直播间并建立播放/信令连接。
4. 观众发送聊天、礼物或其他互动，系统展示并记录结果。
5. 主播结束直播，系统保存结束状态并处理录播。
6. 录播登记为可回看的资源。

备选/异常流程：SRS 不可用；摄像头权限拒绝；主播断连；观众重连；礼物币不足；重复扣款；录播上传/登记失败；服务重启后状态恢复。

当前风险：直播房间、观众和消息保存在进程内 `Map`，必须持久化或经教师确认缩减/排除。

## UC06 举报、审核与治理处置

| 字段 | 内容 |
| --- | --- |
| 需求编号 | `REQ06` |
| 参与者 | 普通用户、管理员、AI 辅助服务（可选） |
| 触发条件 | 用户发现违规视频/评论/弹幕并发起举报，管理员需要处理 |
| 前置条件 | 举报者已登录；目标存在；管理员已通过权限校验 |
| 可验证结果 | 举报记录可查；管理员处置有状态、原因和操作者；目标内容按决定隐藏/下架或保留 |
| 主要模块 | `report`、`admin`、`agent`、`comment-ai`、管理后台 |
| 追溯编号 | `SYS-SEQ06`、`COMP-SEQ06`、`OBJ-SEQ06`、`UNIT-TC06`、`INT-TC06`、`E2E-TC06` |

主成功流程：

1. 用户对视频、评论或弹幕提交举报原因。
2. 系统验证目标并保存待处理举报。
3. 管理员在治理后台查看举报和相关内容。
4. 管理员选择通过处置或驳回举报，并填写原因。
5. 系统更新举报状态与目标内容状态，保存操作者和时间。
6. 用户或管理员可验证最终结果。

备选/异常流程：目标不存在；重复举报；普通用户调用管理员接口；AI 服务不可用；内容服务状态更新失败；处置重试/回滚。
