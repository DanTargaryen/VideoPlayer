- 修复状态：已关闭。
- 最终验证：不存在关键词返回 `counts.video=0`，页面沿用现有无结果提示。

### BUG-BASE01-UC02-02

- 缺陷编号：`BUG-BASE01-UC02-02`
- 复现步骤：普通用户打开已发布视频详情；使该视频的媒体清单请求返回 503；点击播放器并观察播放区。
- 期望结果：页面显示媒体暂不可用或加载失败的明确状态，其他详情内容保持可用。
- 实际结果：详情页仍在，但播放器只显示 `00:00 / 00:00`，没有错误说明。
- 修复状态：已关闭。
- 修复验证：在独立 MySQL、Redis、MinIO、SRS 环境中使用 headed Chrome 将真实媒体清单请求强制返回 503；页面显示 `播放失败`、`视频加载失败，媒体暂不可用，请稍后重试。` 和 `重新加载`，同时标题、简介、评论与相关推荐保持可用；点击重试后第二次媒体请求仍为 503，错误状态再次明确显示。

### BUG-BASE01-UC03-01

- 缺陷编号：`BUG-BASE01-UC03-01`
- 复现步骤：普通创作者进入投稿页；标题填写 `BASE01-UC03-INVALID`；选择一个内容为纯文本的 `.txt` 文件作为视频；提交创建。
- 期望结果：前端或后端拒绝无效媒体并显示明确错误，不创建稿件和存储对象。
- 实际结果：对象上传接口和稿件创建接口均返回 201，页面跳转到用户中心并出现一个 0 秒草稿，隔离 MinIO 中存在该文本对象。
- 修复状态：已关闭。
- 最终验证：纯文本伪装 MP4 返回 400；失败前后 Asset/Video/Object 计数完全一致；真实 MP4 返回 201 并可创建 Draft。

### BUG-BASE01-UC05-01

- 缺陷编号：`BUG-BASE01-UC05-01`
- 复现步骤：主播使用摄像头模式开始直播；结束直播；在“保存直播内容”对话框选择“保存为稿件”；观众刷新已结束的直播间并播放回放。
- 期望结果：回放对象以浏览器支持的媒体类型返回，观众可在直播间播放已登记回放。
- 实际结果：保存接口成功、房间得到回放 URL 且创建视频稿件；对象响应 `Content-Type: text/plain`，浏览器报告 `MEDIA_ELEMENT_ERROR: Format error`，回放无法播放。
- 修复状态：已关闭。
- 最终验证：真实 MediaRecorder WebM 与转码 MP4 的数据库 MIME、MinIO Header 和文件扩展名一致；Chrome 两种资源均 `readyState=4`、320×240、无媒体错误。

### BUG-BASE01-UC06-01

- 缺陷编号：`BUG-BASE01-UC06-01`

- 修复状态：已关闭。
- 最终验证：8 路并发只返回一个 PENDING ID；处理释放键后新举报获得不同 ID。
