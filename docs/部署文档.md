# 观澜视频平台部署文档

## 1. 文档目的

本文档说明“观澜视频平台”的开发环境、局域网演示环境和生产环境部署方式。项目采用前后端分离架构：

- 前端：Vue 3 + TypeScript + Vite
- 后端：NestJS + Prisma
- 数据库：MySQL
- 缓存/消息辅助：Redis
- 对象存储：MinIO
- 直播媒体服务：SRS
- 媒体处理：FFmpeg / FFprobe

项目根目录为：

```text
VideoPlayer/
  frontend/   前端应用
  backend/    后端 API 服务
  deploy/     部署与容器配置
  scripts/    本地开发启动脚本
  docs/       项目文档
```

## 2. 环境要求

### 2.1 基础软件

| 软件 | 建议版本 | 用途 |
| --- | --- | --- |
| Node.js | 22 LTS 或更高 | 运行前后端构建和服务 |
| npm | 随 Node 安装 | 工作区依赖管理 |
| MySQL | 8.x 或兼容版本 | 主业务数据库 |
| Docker / Docker Compose | 可选但推荐 | 启动 Redis、MinIO、SRS |
| FFmpeg / FFprobe | 推荐安装 | 视频转码、时长解析、封面抽帧 |

> 说明：如果 Docker 不可用，当前开发脚本仍可启动前后端，但 Redis、MinIO、SRS 容器不会被自动拉起。此时完整 RTC 直播链路不可用，直播观看会退回兼容帧模式；如果 MinIO 也不可用，应改用已有 MinIO 服务或设置本地存储模式。

### 2.2 端口规划

| 端口 | 服务 | 说明 |
| --- | --- | --- |
| 5173 | Vite 前端开发服务 | 本地开发访问入口 |
| 3000 | NestJS 后端 API | 默认 API 服务端口 |
| 3306 | MySQL | 数据库 |
| 6379 | Redis | 缓存/后台任务辅助 |
| 9000 | MinIO API | 对象存储访问地址 |
| 9001 | MinIO Console | MinIO 管理控制台 |
| 1935 | SRS RTMP | 直播推流 |
| 8080 | SRS HTTP-FLV/HLS | 直播播放 |
| 1985 | SRS API | SRS 管理 API |
| 8000/udp | SRS WebRTC | WebRTC 直播链路 |

## 3. 获取代码与安装依赖

进入项目根目录后执行：

```bash
npm install
```

如果依赖安装失败，优先检查 Node.js 版本和网络代理配置。安装完成后，根目录、`frontend/` 和 `backend/` 下都应具备对应的 `node_modules` 工作区依赖。

## 4. 环境变量配置

### 4.1 后端环境变量

复制示例文件：

```bash
cp backend/.env.example backend/.env
```

核心配置如下：

```env
PORT=3000
DATABASE_URL="mysql://root:proot@127.0.0.1:3306/video_player"

REDIS_HOST=127.0.0.1
REDIS_PORT=6379

STORAGE_BACKEND=minio
MINIO_ENDPOINT=127.0.0.1
MINIO_PORT=9000
MINIO_USE_SSL=false
MINIO_ROOT_USER=minioadmin
MINIO_ROOT_PASSWORD=minioadmin
MINIO_BUCKET=video-player
MINIO_PUBLIC_BASE_URL=http://127.0.0.1:9000
MINIO_PUBLIC_DOWNLOAD=true

SRS_RTMP_BASE=rtmp://127.0.0.1/live
SRS_PLAY_BASE=http://127.0.0.1:8080/live
SRS_API_BASE=http://127.0.0.1:1985
SRS_WEBRTC_BASE=webrtc://127.0.0.1/live

FFMPEG_PATH=ffmpeg
FFPROBE_PATH=ffprobe
```

如果部署在服务器上，需要把 `127.0.0.1` 替换为服务器内网地址、公网域名或反向代理地址。尤其是 MinIO 和 SRS 的公开访问地址，必须是浏览器能访问到的地址。

### 4.2 前端环境变量

复制示例文件：

```bash
cp frontend/.env.example frontend/.env
```

开发环境推荐保持默认：

```env
VITE_API_BASE_URL=/api/v1
VITE_AI_SUMMARY_TIMEOUT_MS=120000
VITE_UPLOAD_TIMEOUT_MS=0
```

前端开发服务通过 Vite 代理访问后端。生产环境如果由 Nginx 统一代理 `/api/v1`，也可以继续使用 `/api/v1`。

## 5. 数据库初始化

### 5.1 创建数据库

如果使用默认本机 MySQL：

```bash
MYSQL_PWD=proot mysql -h 127.0.0.1 -P 3306 -u root < deploy/mysql/init.sql
```

也可以使用项目脚本：

```bash
npm run db:init
```

该脚本会检查 MySQL 连接、创建数据库、生成 Prisma Client、同步表结构并写入演示数据。

### 5.2 手动执行 Prisma 初始化

如果需要分步骤执行：

```bash
npm --workspace backend run prisma:generate
npm --workspace backend run db:migrate
npm --workspace backend run db:seed
```

这组命令默认适用于全新本地数据库。已有数据库必须先备份，并按 8.3 节的 existing-database baseline 流程确认 Schema 一致；不能用删除数据卷、`db push` 或跳过守卫的方式处理 `P3005`。

## 6. 本地开发部署

### 6.1 一键启动

在项目根目录执行：

```bash
npm run dev
```

脚本会执行以下操作：

1. 读取 `backend/.env` 或根目录 `.env`。
2. 检查 MySQL 是否可用。
3. 确认数据库是否存在。
4. 如果 Docker 可用，启动 Redis、MinIO、SRS。
5. 启动后端开发服务。
6. 启动前端 Vite 开发服务。

启动成功后访问：

```text
http://localhost:5173/
```

后端 API 地址：

```text
http://127.0.0.1:3000/api/v1
```

健康检查：

```bash
curl http://127.0.0.1:3000/api/v1/health
```

正常返回示例：

```json
{"code":0,"message":"ok","data":{"status":"ok","service":"backend"}}
```

### 6.2 分别启动前后端

如果需要单独调试：

```bash
npm run dev:backend
npm run dev:frontend
```

### 6.3 停止开发服务

如果服务运行在当前终端，按：

```text
Ctrl+C
```

如果只需要停止 Docker 依赖服务：

```bash
npm run dev:down
```

> 注意：`npm run dev:down` 只停止 Docker Compose 管理的 Redis、MinIO、SRS，不会停止已经手动启动的 Vite 或 NestJS 进程。

## 7. 局域网演示部署

如果需要让同一局域网下的其他电脑访问演示地址，并且需要摄像头、麦克风、屏幕共享等直播能力，应使用 HTTPS 开发模式：

```bash
npm run dev:lan
```

脚本会：

1. 自动检测本机局域网 IP。
2. 生成本地 HTTPS 证书。
3. 以 `0.0.0.0` 启动 Vite。
4. 将 SRS 公共地址配置为局域网 IP。

启动成功后终端会输出类似地址：

```text
https://10.124.244.156:5173/
```

其他电脑应访问这个 HTTPS 地址，而不是 `http://<IP>:5173`。原因是浏览器在非安全来源下会禁用摄像头、麦克风和屏幕共享。

如果自动检测 IP 不正确，可以显式指定：

```bash
LAN_HOST=10.124.244.156 npm run dev:lan
```

首次访问本地开发证书时，浏览器可能提示“不安全”或“证书不受信任”，选择继续访问即可。

## 8. 生产环境部署

生产环境推荐将后端作为 Node 服务运行，将前端构建为静态文件并交给 Nginx 托管。

### 8.1 安装依赖

```bash
npm install
```

### 8.2 准备后端环境变量

编辑：

```bash
backend/.env
```

至少确认以下配置：

```env
PORT=3000
DATABASE_URL="mysql://<user>:<password>@<mysql-host>:3306/video_player"
REDIS_HOST=<redis-host>
REDIS_PORT=6379
STORAGE_BACKEND=minio
MINIO_ENDPOINT=<minio-host>
MINIO_PORT=9000
MINIO_PUBLIC_BASE_URL=https://<your-domain>/minio
SRS_RTMP_BASE=rtmp://<your-domain>/live
SRS_PLAY_BASE=https://<your-domain>/live
SRS_API_BASE=http://<srs-host>:1985
SRS_WEBRTC_BASE=webrtc://<your-domain>/live
```

如果没有公网域名，`<your-domain>` 可以替换为服务器 IP；但直播和浏览器媒体能力更推荐使用 HTTPS 域名。

### 8.3 初始化数据库

`db:migrate` 默认只直接允许本地验收数据库、Compose/Kind 内的 `mysql:3306/video_player`，以及名称包含 `test` 的本地隔离库。生产或其他远端数据库必须在单次命令中同时提供精确目标与显式确认；不要把以下确认变量长期写入 `.env`：

```bash
npm --workspace backend run prisma:generate

MIGRATION_DEPLOY_ALLOWED_TARGET=<mysql-host>:3306/video_player \
MIGRATION_DEPLOY_CONFIRM=DEPLOY_MIGRATIONS \
  npm --workspace backend run db:migrate
```

如果目标数据库已经包含与当前 `schema.prisma` 等价的业务表，但还没有登记 `20260826000000_init`，必须先备份数据库，再执行受保护的 baseline：

```bash
BASELINE_EXISTING_ALLOWED_TARGET=<mysql-host>:3306/video_player \
BASELINE_EXISTING_CONFIRM=BASELINE \
  npm --workspace backend run db:baseline-existing
```

`db:baseline-existing` 会先执行 Schema diff；只有 Schema 完全一致时才会将 `20260826000000_init` 标记为已应用并继续 `migrate deploy`。如果检测到漂移，命令会在 `migrate resolve` 前失败，此时必须先人工核对并制定迁移方案，不能修改确认值绕过检查。该命令需要执行机器可使用 MySQL 命令行客户端。

baseline 完成后，后续部署仍使用同样的单次迁移授权：

```bash
MIGRATION_DEPLOY_ALLOWED_TARGET=<mysql-host>:3306/video_player \
MIGRATION_DEPLOY_CONFIRM=DEPLOY_MIGRATIONS \
  npm --workspace backend run db:migrate
```

仅在明确需要演示数据、且目标不是共享或生产数据库时才执行 Seed：

```bash
npm --workspace backend run db:seed
```

如果生产环境不希望写入演示数据，可跳过 `db:seed`，但需要自行创建管理员或必要初始化账号。

### 8.4 构建项目

```bash
npm run build:backend
npm run build:frontend
```

构建产物：

```text
backend/dist/
frontend/dist/
```

### 8.5 启动后端

直接启动：

```bash
npm --workspace backend run start
```

或：

```bash
node backend/dist/main.js
```

```bash
npm install -g pm2

pm2 save
```

```bash

```

```bash

```

停止：

```bash

```

### 8.6 部署前端静态文件

将 `frontend/dist/` 部署到 Web 服务器，例如：

```text
/var/www/video-player
```

Nginx 示例配置：

```nginx
server {
    listen 80;
    server_name your-domain.example.com;

    root /var/www/video-player;
    index index.html;

    client_max_body_size 2048m;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/v1/ {
        proxy_pass http://127.0.0.1:3000/api/v1/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

如果使用 HTTPS，建议用 Certbot 或平台证书管理工具配置 TLS。

## 10. 文件上传与媒体处理

默认使用 MinIO：

```env
STORAGE_BACKEND=minio
MINIO_BUCKET=video-player
```

上传链路包括：

1. 原始视频上传到 MinIO。
2. 后端读取视频元信息。
3. 使用 FFmpeg 转码为 MP4。
4. 如果没有上传封面，自动抽帧生成封面。
5. 前端通过返回的 URL 播放视频或展示封面。

如果部署在 HTTPS 页面下，但 MinIO 仍是 HTTP 地址，浏览器可能阻止混合内容。推荐方案：

- 使用 HTTPS 反向代理暴露 MinIO 资源；
- 或将 `MINIO_PUBLIC_BASE_URL` 配置为同源代理地址；
- 或使用项目后端媒体代理接口处理 HTTP 媒体资源。

## 11. 直播部署注意事项

直播涉及浏览器媒体权限和 SRS 服务，部署时需注意：

1. 摄像头、麦克风、屏幕共享必须在安全来源下使用，即 `https://` 或 `localhost`。
2. 局域网其他电脑访问时，应使用 `npm run dev:lan` 输出的 HTTPS 地址。
3. SRS 的 `CANDIDATE` 应配置为其他设备可访问的服务器 IP 或域名。
4. 生产环境下，SRS 的 RTMP、HTTP、WebRTC 端口需放通防火墙。

局域网示例：

```bash
SRS_CANDIDATE=10.124.244.156 LAN_HOST=10.124.244.156 npm run dev:lan
```

生产环境示例：

```env
SRS_RTMP_BASE=rtmp://live.example.com/live
SRS_PLAY_BASE=https://live.example.com/live
SRS_API_BASE=http://127.0.0.1:1985
SRS_WEBRTC_BASE=webrtc://live.example.com/live
```

## 12. 常见问题

### 12.1 端口 3000 被占用

查看占用进程：

```bash
lsof -nP -iTCP:3000 -sTCP:LISTEN
```

停止占用进程后重新启动，或临时换端口：

```bash
PORT=3001 npm run dev
```

### 12.2 端口 5173 被占用

查看占用进程：

```bash
lsof -nP -iTCP:5173 -sTCP:LISTEN
```

可以设置 Vite 端口：

```bash
VITE_DEV_PORT=5174 npm run dev
```

### 12.3 Docker 不可用

如果终端显示 Docker 不可用，前后端仍可启动，但 Redis、MinIO、SRS 不会自动启动。需要完整上传和直播能力时，应启动 Docker Desktop 或安装 Docker Engine。

### 12.4 本机可以打开，局域网其他电脑打不开

检查：

1. 前端是否以 `0.0.0.0` 启动。
2. 是否使用 `npm run dev:lan`。
3. 防火墙是否放通 `5173` 和后端相关端口。
4. 访问地址是否为当前机器的真实局域网 IP。
5. 浏览器是否接受了本地 HTTPS 证书。

### 12.5 直播无法开播

常见原因：

1. 使用了 `http://<IP>:5173`，浏览器禁用了摄像头/麦克风。
2. SRS 没有启动。
3. SRS `CANDIDATE` 配置不是可访问 IP。
4. 防火墙未放通 WebRTC UDP 端口。

本机调试可以使用：

```text
http://localhost:5173/
```

局域网演示应使用：

```text
https://<LAN-IP>:5173/
```

### 12.6 视频或封面无法显示

检查：

1. MinIO 是否运行。
2. `MINIO_PUBLIC_BASE_URL` 是否能被浏览器访问。
3. HTTPS 页面是否加载了 HTTP 媒体资源。
4. 后端媒体代理是否正常。
5. 浏览器控制台是否存在 mixed content 错误。

### 12.7 评论或弹幕提示未登录

检查：

1. 浏览器是否已登录。
2. `localStorage` 中是否存在 `vp_token`。
3. 后端是否刚重启过。
4. 后端健康检查是否正常。

健康检查：

```bash
curl http://127.0.0.1:3000/api/v1/health
```
