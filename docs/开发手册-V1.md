# 开发手册 V1

## 1 文档目的

本文档用于指导观澜视频平台的开发实施，明确工程目录、技术选型、模块边界、核心业务流程、接口规范、数据库对象、部署方式和协作约定，确保后续编码、联调、测试和文档编写保持一致。

## 2 项目概述

### 2.1 产品目标

构建一个面向视频观看者、用户与管理员的综合视频平台，首版支持：

- 短视频、中视频、长视频统一发布与观看
- 推荐、分区、搜索、视频详情、相关推荐
- 评论、二级回复、视频弹幕、关注订阅
- 真实推流直播、直播聊天、直播弹幕、录播回看
- 用户中心与管理员审核后台
- 每日登录礼物币领取与直播礼物模拟
- Agent 审核辅助

### 2.2 用户角色

| 角色 | 权限概述 |
| --- | --- |
| 游客 | 浏览首页、搜索、观看公开视频与直播 |
| 用户 | 点赞、收藏、评论、回复、发送视频弹幕、关注、领取礼物币、发送礼物、投稿、管理视频、提交审核、开播、查看数据、查看违规提醒 |
| 管理员 | 审核内容、处理举报、下架内容、封禁账号、管理分区与推荐位、查看 Agent 建议 |

## 3 技术栈与工程决策

### 3.1 前端技术栈

- Vue 3
- TypeScript
- Vite
- Pinia
- Vue Router
- Element Plus
- Axios
- ECharts（用于数据看板）
- Hls.js / flv.js（根据播放协议选择）

### 3.2 后端技术栈

- Node.js 20+
- NestJS
- TypeScript
- Prisma 或 TypeORM（二选一，建议 Prisma）
- MySQL 8
- Redis
- WebSocket（Nest Gateway）
- BullMQ（异步任务队列，可选但建议）

### 3.3 媒体与直播技术栈

- MinIO：对象存储，用于保存原始视频、封面、转码视频和录播文件
- FFmpeg：转码、抽帧、时长解析、录播处理
- SRS：直播推流、转流、回看支持
- Nginx：反向代理与静态资源入口

### 3.4 Agent 接入原则

- Agent 只做审核辅助，不直接自动执行封禁或删除
- Agent 输出结构化结果：风险等级、命中原因、建议处理动作、理由摘要
- Agent 接口需抽象为独立服务，便于替换模型供应商

## 5 系统架构说明

### 5.1 总体架构

系统采用前后端分离 + 单体模块化后端架构：

- Vue 前端负责页面渲染、状态管理和用户交互
- NestJS 后端负责业务逻辑、权限校验、接口输出、任务调度
- MySQL 存储业务主数据
- Redis 存储缓存、会话、热点计数和消息辅助数据
- MinIO 存储视频文件、封面、录播文件
- FFmpeg 负责媒体处理
- SRS 负责直播推流与播放分发
- WebSocket 负责直播聊天、直播弹幕、审核通知等实时消息

### 5.2 核心链路

#### 视频投稿链路

1. 用户上传视频文件和封面
2. 后端生成媒体任务并写入 `PROCESSING` 状态
3. FFmpeg 完成转码、抽帧、时长提取
4. 用户提交审核，状态切换为 `PENDING_REVIEW`
5. Agent 生成风险提示
6. 管理员审核通过后切换为 `PUBLISHED`
7. 视频进入搜索、推荐和公开播放范围

#### 视频消费链路

1. 用户进入首页或搜索结果页
2. 前端请求推荐流/搜索接口
3. 后端根据规则排序返回公开视频列表
4. 用户进入视频详情页，加载播放器、评论、相关推荐、弹幕配置
5. 用户互动行为进入行为日志，为规则推荐提供统计输入

#### 直播链路

1. 用户创建直播间并完成开播准备
2. 推流端向 SRS 推送 RTMP 流
3. SRS 转换为前端可播放协议
4. 前端直播页拉流播放
5. 聊天与弹幕通过 WebSocket 独立下发
6. 直播结束后生成录播文件并提供回看入口

#### 审核链路

1. 视频投稿或评论/弹幕举报进入审核队列
2. Agent 输出风险等级与理由建议
3. 管理员在审核后台处理
4. 系统记录审核日志、处理结果与操作者信息

## 7 核心业务规则

### 7.1 内容分区规则

固定分区为：推荐、娱乐、学习、游戏、科技、直播。视频内容需至少归属一个非“推荐”业务分区，推荐分区由系统自动生成。

### 7.2 审核规则

- 首版采用先审后发
- 未审核通过的视频不进入公开播放范围
- 被驳回内容可修改后重新提交审核
- 评论与弹幕支持人工审核与举报后复核

### 7.3 游客规则

- 游客可浏览首页、分区、搜索结果、视频详情与直播间
- 游客不可点赞、收藏、评论、弹幕、关注、发送礼物、投稿、开播

### 7.4 礼物币规则

- 注册用户每日首次登录可领取一定数量礼物币
- 礼物币仅用于平台内礼物发送，不可提现
- 礼物币余额、领取记录、送礼记录需落库
- 首版可不实现复杂收益结算，仅记录礼物行为与展示效果
- 管理员账号不能直接从普通登录入口进入，需先通过管理密钥 `123456` 开启管理入口

### 7.5 推荐规则

首版采用规则版推荐，可综合以下因素：

- 视频发布时间
- 播放量
- 点赞数
- 收藏数
- 评论数
- 用户分区偏好
- 用户关注关系
- 内容审核状态

## 10 接口规范

### 10.1 基本约定

- 协议：HTTP/HTTPS + JSON
- 路由前缀：`/api/v1`
- 鉴权方式：Bearer Token
- 分页参数：`page`、`pageSize`
- 统一返回格式：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

### 10.2 错误码建议

- `0`：成功
- `40001`：参数错误
- `40101`：未登录
- `40301`：无权限
- `40401`：资源不存在
- `40901`：状态冲突
- `50001`：服务内部错误

### 10.3 首批接口清单

- `/auth/register`
- `/auth/login`

## 11 实时通信设计

### 11.1 WebSocket 通道划分

- `live-chat`：直播聊天
- `live-danmaku`：直播弹幕
- `audit-notify`：审核结果通知
- `system-notify`：系统消息通知

### 11.2 实时设计原则

- 视频弹幕以接口写入 + 播放器时间轴拉取为主
- 直播聊天与直播弹幕以 WebSocket 实时广播为主
- 所有实时消息都要经过基础敏感词过滤与频控

## 12 安全与治理

### 12.1 基础安全

- 密码加密存储
- 基于角色的接口权限控制
- 上传文件类型和大小校验
- 关键操作写入审计日志

### 12.2 社区治理

- 敏感词过滤
- 举报入口
- 审核队列
- 用户禁言/封禁
- Agent 风险分层提示

## 13 开发流程约定

### 13.1 分支策略

- `main`：稳定分支
- `dev`：集成分支
- `feature/*`：功能分支
- `fix/*`：修复分支

### 13.2 代码规范

- 前后端统一 TypeScript
- 强制开启 ESLint 和 Prettier
- 接口 DTO、数据库模型、前端类型定义命名保持一致
- 所有公共类型与枚举统一维护

### 13.3 联调规则

- 先产出接口清单，再编码
- 涉及状态机的接口需补充时序图或流程图
- 数据库表变更需同步更新数据库设计文档和接口文档
