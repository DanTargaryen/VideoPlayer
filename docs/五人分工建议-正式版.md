# 五人分工建议（正式版）

## 1. 分工原则

结合当前项目进度与剩余任务，建议项目组采用“五人协同、前后端分离、测试与文档独立兜底”的方式推进。分工时遵循以下原则：

- 以“可演示的完整链路”为优先目标，优先保证首页浏览、搜索、视频详情、投稿审核、后台治理、直播基础能力能够稳定展示。
- 以前后端职责边界清晰为原则，减少多人同时修改同一模块导致的冲突。
- 将“前端体验优化”单独提升到核心任务层级，不再视为收尾工作，而作为答辩质量的重要组成部分。
- 由专人负责测试、文档和交付整合，确保项目最终能够跑通、讲清、演示稳定。

## 2. 推荐的五人分工方案

### 成员 A：主站前端与视觉优化负责人

职责范围：

- 负责平台主站用户侧页面的前端实现与整体视觉优化，包括首页推荐页、搜索结果页、视频详情页、用户主页、关注流页面、通知中心页面。
- 主导全站视觉规范制定与主站组件抽象，重点解决当前页面样式不统一、布局粗糙、视觉层次弱的问题。

核心任务：

- 统一主站的颜色体系、卡片样式、按钮风格、间距规范、字体层级。
- 优化首页、搜索页、详情页的布局与交互体验。
- 增加空状态、加载状态、错误提示等细节表现。
- 抽离可复用组件，如内容卡片、统计卡片、筛选栏、页面标题区等。
- 与成员 B 协调，保证创作者端与直播端页面风格统一。

交付物：

- 主站页面优化后的前端代码。
- 全站通用 UI 组件。
- 前端视觉规范初稿。
- 可用于答辩展示的主站页面截图。

建议优先级：P0

### 成员 B：创作者端与直播前端负责人

职责范围：

- 负责创作者侧页面与直播相关前端页面的实现与优化，包括用户中心、投稿与稿件管理页面、审核记录与违规提醒展示、直播间页面、直播聊天区、直播弹幕展示区、礼物区与录播入口页面。
- 重点任务不仅是补齐页面功能，还需要将当前偏占位式的创作者端和直播端页面重构为可演示、可操作、视觉完整的正式页面。

核心任务：

- 完善用户中心的数据概览、稿件管理、审核记录、违规提醒等页面。
- 补齐直播间基础布局、互动区、聊天区、弹幕区、礼物区。
- 与成员 A 共用统一视觉规范，保持整体风格一致。
- 提升创作者流程的完整性和可演示性。

交付物：

- 用户中心完整前端代码。
- 直播间相关页面代码。
- 创作者流程演示页面。
- 直播前端展示素材与截图。

建议优先级：P0

### 成员 C：内容业务后端负责人

职责范围：

- 负责平台内容主链路相关的后端功能开发与接口完善，包括登录与鉴权、用户资料与用户主页、推荐流与分区内容、搜索模块、视频详情模块、评论与回复、视频弹幕、关注与关注流、通知中心、创作者中心相关接口。
- 主要承担内容消费与互动闭环的后端建设工作，是前端主站与创作者端联调的主要接口负责人。

核心任务：

- 补齐推荐流、搜索、分区浏览、热门内容等接口细节。
- 优化评论、弹幕、关注、通知等业务逻辑。
- 完善稿件编辑、审核记录、用户主页等接口返回结构。
- 统一 DTO、参数校验和异常处理。
- 保证接口命名、字段命名与文档保持一致。

交付物：

- 内容业务后端代码。
- 更新后的接口结构说明。
- 联调可用的稳定 API。
- 与数据库字段一致的业务返回格式。

建议优先级：P0

### 成员 D：直播后端、媒体处理与部署负责人

职责范围：

- 负责项目中技术风险最高的后端与基础设施部分，包括 MinIO 文件上传与对象存储、FFmpeg 媒体处理链路、SRS 直播推流与播放链路、直播开播/停播状态管理、录播生成与回看资源、礼物币后端逻辑、项目部署与运行环境搭建。
- 直接决定项目能否完成直播链路演示和媒体资源真实处理，因此属于核心保障角色。

核心任务：

- 打通视频文件上传、资源入库、转码、抽帧、时长解析链路。
- 实现直播间开播、停播、播放地址生成与状态切换。
- 完成录播资源处理与回看入口支持。
- 补齐礼物币、礼物发送等直播相关后端逻辑。
- 编写部署说明，确保答辩前环境稳定。

交付物：

- 直播后端代码。
- 媒体处理代码与脚本。
- 部署文档与环境说明。
- 可用于答辩的直播演示环境。

建议优先级：P0

### 成员 E：审核后台、测试与文档负责人

职责范围：

- 负责平台治理端、测试与交付整合工作，包括审核后台页面与治理逻辑、视频审核、评论审核、弹幕审核、举报处理、筛选器、状态标签、处理备注、Agent 结果展示、测试用例编写与回归测试、部署文档、用户手册、答辩材料整理。
- 主要作用是确保系统不仅能开发，而且能稳定交付、能顺利答辩。

核心任务：

- 完善后台治理能力与审核交互流程。
- 增强后台的筛选、定位、处理备注与统计展示能力。
- 编写并执行关键链路测试用例。
- 汇总部署文档、测试报告、用户说明。
- 整理答辩 PPT 所需截图、流程图和演示脚本。

交付物：

- 审核后台代码。
- 测试清单与回归记录。
- 部署文档。
- 用户手册。
- 答辩材料初稿。

建议优先级：P0

## 3. 当前阶段的重点任务安排

结合现阶段项目状态，建议五位成员按照以下优先顺序推进：

### 第一优先级：必须尽快完成

- 成员 A：主站视觉统一与页面优化。
- 成员 B：用户中心与直播间页面补齐。
- 成员 C：搜索、推荐、评论、弹幕、稿件编辑等内容接口完善。
- 成员 D：上传、媒体处理、直播链路与部署环境打通。
- 成员 E：审核后台增强、测试用例编写、文档整理。

### 第二优先级：在主链路稳定后继续完善

- 搜索页高级筛选与排序体验。
- 用户中心粉丝趋势与直播历史。
- 礼物币完整业务闭环。
- 后台治理筛选条件增强。
- Agent 审核结果真实接入。

## 4. 对前端优化的特别要求

考虑到当前前端页面观感较弱，前端优化不应作为附属任务，而应作为主任务推进。具体要求如下：

- 主站、创作者端、直播端、后台端应统一视觉风格。
- 必须统一颜色、卡片、按钮、表单、标签、间距、阴影与圆角设计。
- 页面需具备完整的空状态、加载状态、错误提示与交互反馈。
- 视频卡片、用户卡片、统计卡片、审核卡片等应组件化。
- 首页、搜索页、详情页、用户中心和直播页需达到可直接用于答辩展示的界面质量。

建议由成员 A 主导视觉规范，成员 B 配合落地，避免多人各自设计导致风格不统一。

## 5. 协作建议

为了降低冲突并提高效率，建议团队执行以下协作方式：

- 成员 A、B 负责前端不同页面域，但共用统一组件和视觉规范。
- 成员 C、D 负责不同后端模块，尽量避免修改同一服务文件。
- 成员 E 尽早介入联调与测试，不要等到所有开发结束后才开始检查。
- 接口字段、数据库字段、文档描述必须保持命名一致。
- 每完成一个主要功能后，立即同步文档与 TODO，避免实现与文档脱节。
