## 2. 测试代码与复现方式

- 测试源码：`backend/test/integration-api.e2e-spec.ts`
- Agent/AI 测试源码：`backend/test/agent-ai.e2e-spec.ts`
- 后端快捷命令：`npm run test:api`
- Agent/AI 快捷命令：`npm run test:agent-ai`
- 原始集成测试 JSON：`test-results/integration-api-latest.json`（由 `test:api` 自动生成，受 `.gitignore` 保护）
- 原始 Agent/AI JSON：`test-results/agent-ai-latest.json`（由 `test:agent-ai` 自动生成，受 `.gitignore` 保护）
- 原始后端全量 JSON：`test-results/backend-all-latest.json`（验证命令生成，受 `.gitignore` 保护）

从仓库根目录执行：

```bash
npm ci
npm --workspace backend run prisma:generate
export INTEGRATION_DATABASE_URL='<云端测试连接串>'
export ALLOW_REMOTE_INTEGRATION_DATABASE=true
npm run test:api
```

`INTEGRATION_DATABASE_URL` 应通过本地环境或 CI Secret 注入，不写入代码、日志或测试报告。`test:api` 每次都会重新生成 `test-results/integration-api-latest.json`，任何 Jest 失败均以非零退出码结束命令。

真实 Agent/AI 复现命令：

```bash
npm ci
npm --workspace backend run prisma:generate
export INTEGRATION_DATABASE_URL='<云端测试连接串>'
export ALLOW_REMOTE_INTEGRATION_DATABASE=true
export DASHSCOPE_API_KEY='<模型密钥>'
export ALLOW_REAL_AI_CALLS=true
npm run test:agent-ai
```

`ALLOW_REAL_AI_CALLS=true` 是费用和外部网络调用的显式开关。普通 `npm test` 明确排除 `agent-ai.e2e-spec.ts`，不会意外调用模型；真实模型套件失败时，`test:agent-ai` 仍以非零退出码停止。

完整后端验证命令：

```bash
INTEGRATION_DATABASE_URL='<云端测试连接串>' \
ALLOW_REMOTE_INTEGRATION_DATABASE=true \
npm --workspace backend exec -- jest --config jest.config.cjs --runInBand \
  --testPathIgnorePatterns=agent-ai.e2e-spec.ts \
  --json --outputFile=../test-results/backend-all-latest.json
npm run lint:backend
npm run build:backend
```

## 7. 已知限制与后续测试范围

1. 本轮不是端到端页面测试；没有验证 Vue 页面、浏览器交互和前后端完整页面流程。
2. 按用户最新要求，MinIO 不再纳入本任务测试范围；不能根据本报告判断真实 MinIO 上传、下载是否可用。
3. 本轮只验证 SRS 不可用时的降级，未验证真实 SDP 交换、推流、拉流和录播成功链路。
4. 审核 Agent 的 `/agent/review-preview` 和 `/agent/results` 当前仍是固定 Mock/空结果，标记为待实现，本轮不补实现且不计入通过。
5. `@grok` 已验证评论 API 和任务入队；为避免领取云端其他用户任务，本轮没有启动真实共享 worker，因此“机器人最终回复评论”仍未形成真实外部验证结论。
6. 本轮真实验证 DashScope/Qwen 在站内助手、视频摘要和视频问答中的调用，但外部模型输出具有非确定性；测试只断言接口、模型标识、非空结果和持久化，不断言固定文案。
7. 按项目实际环境要求，本轮使用共享云端 MySQL；通过显式远程执行开关、真实模型费用开关、唯一前缀、后台 worker 替换和定向清理降低风险。正式 CI 仍更适合使用专用云端测试库。
8. 当前后端异常响应仍采用 Nest 默认错误结构；本轮验证了状态码和错误信息，没有把 API 文档中的业务错误码 `40001/40101/...` 视为已实现。
9. backend 默认 lint 只扫描 `src/**/*.ts`；本轮另行对两个测试文件执行 ESLint 并通过。
10. npm 安装报告 16 个依赖漏洞（1 low、3 moderate、12 high）；它不影响本轮功能测试结论，但需要单独进行依赖安全评估，不能直接运行可能产生破坏性升级的 `npm audit fix`。

## 8. 最终判定

在 `main@b459880ffe1a` 对应的迁移前工作树上，基础集成/API 16 项和独立 Agent/AI 5 项共 21 项专用验收用例全部通过，失败 0、跳过 0；当时的后端常规回归 18/18、两个测试文件 ESLint 和 Nest build 同时通过。真实模型在该历史执行中已覆盖站内助手、视频摘要和视频问答链路；这不等同于当前 `zzz2` HEAD 的真实模型复跑。MinIO 按要求排除，审核 Agent 保持 Mock/待实现，`@grok` 最终 worker 回复、真实 SRS 成功链路和浏览器 E2E 不在本报告通过结论内。
