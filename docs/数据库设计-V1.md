# 数据库设计 V1

## 1 设计目标

本文档用于定义观澜视频平台首版的核心数据库实体、字段设计、主外键关系、状态字段与索引建议，作为后续 ORM 建模、接口开发、测试数据构造和详细设计的依据。

数据库选型：MySQL 8
字符集建议：`utf8mb4`

## 2 设计原则

- 统一使用自增主键 `BIGINT` 或雪花 ID，首版建议使用 `BIGINT`
- 通用状态字段使用枚举字符串或小整型，需要在代码中统一维护
- 所有表均保留基础审计字段：`created_at`、`updated_at`
- 删除优先采用逻辑删除或状态失效，而非直接物理删除
- 审核、处罚、礼物币等关键行为必须保留流水或日志记录

## 3 核心实体关系概览

### 3.1 用户相关

- `user` 1:1 `user_profile`
- `user` N:M `role`（首版可简化为用户表内角色字段）
- `user` 1:N `video`
- `user` 1:N `comment`
- `user` N:M `user` 通过 `follow_relation`

### 3.2 视频相关

- `video` 1:N `video_asset`
- `video` N:1 `category`
- `video` N:M `tag` 通过 `video_tag_relation`
- `video` 1:N `video_review`
- `video` 1:N `comment`
- `video` 1:N `video_danmaku`

### 3.3 直播相关

- `user` 1:N `live_room`
- `live_room` 1:N `live_session`
- `live_session` 1:N `live_chat_message`
- `live_session` 1:N `live_danmaku`
- `live_session` 1:1 `live_recording`

### 3.4 治理与运营相关

- `report_record` 可关联视频、评论、弹幕或直播场次
- `audit_log` 记录管理员审核与处罚动作
- `agent_review_result` 可关联视频审核、评论审核、弹幕审核等场景

## 5 关键状态设计

### 5.1 视频状态机

- `DRAFT`：草稿
- `PROCESSING`：媒体处理中
- `PENDING_REVIEW`：待审核
- `REJECTED`：审核驳回
- `PUBLISHED`：已发布
- `OFFLINE`：下架

### 5.2 直播状态机

#### 直播间状态

- `CREATED`
- `READY`
- `LIVING`
- `ENDED`
- `BANNED`

#### 直播场次状态

- `READY`
- `LIVING`
- `ENDED`
- `ABNORMAL`

### 5.3 举报状态

- `PENDING`
- `PROCESSED`
- `REJECTED`

## 6 索引建议

- 用户：`username`、`email`
- 视频：`creator_id`、`category_id`、`status`、`publish_at`
- 评论：`video_id`、`parent_id`、`root_id`
- 弹幕：`video_id + time_offset_ms`、`session_id`
- 直播：`creator_id`、`status`
- 举报：`target_type + target_id`、`status`
- Agent 结果：`target_type + target_id`

## 8 与接口设计的对应关系

- `user`、`user_profile` 对应认证和用户资料接口
- `video`、`video_asset`、`video_review` 对应投稿、审核、播放接口
- `comment`、`video_danmaku` 对应互动接口
- `live_room`、`live_session`、`live_chat_message`、`live_danmaku`、`live_recording` 对应直播与录播接口
- `gift_coin_wallet`、`gift_coin_daily_claim`、`gift_order` 对应礼物币接口
- `report_record`、`audit_log`、`agent_review_result` 对应审核后台与 Agent 接口
